# 本仓默认技术栈

> 适用范围：**以后所有新项目**默认按本文选技术，不再逐个商量。
> 真源在 `D:\project\_规范\`；各项目 `docs/规范/` 只放副本。
> 要偏离默认：需求里写清「本项目例外：用 XXX，原因：YYY」。没写就按默认做。

---

## 1. 默认选型

| 层 | 默认 | 不要默认上 |
|---|---|---|
| Web API（官网 / 后台类） | FastAPI + Uvicorn | 无必要不上第二套框架 |
| Web API（会所 / bot 类） | Flask（对齐现有会所） | 无必要混 FastAPI |
| 数据库访问 | **朴素驱动**：SQLite → 标准库 `sqlite3`；MySQL → PyMySQL | SQLAlchemy / 其他 ORM |
| 表结构变更 | 启动时幂等 `ensure_schema` / 建表脚本（`CREATE IF NOT EXISTS` + 缺列 `ALTER`） | Alembic 等迁移框架当默认 |
| 配置 | `core/config.py` + 环境变量前缀（`APP_` / `ADMIN_` 等） | 硬编码 URL / 端口 / 密钥 |
| 前端（有页面时） | React + TypeScript + Vite；移动端 / Telegram 壳 / 统一按钮见《前端移动与Telegram壳》 | 页面内私自第三套按钮/底栏 |
| 接口契约（有前后端时） | `contracts/openapi.yaml` 为唯一真源 | 前后端口径各写一份 |
| 进程 / 上线 | 项目根 `online.cmd` / `dev.cmd`；本机只用本项目 `.venv` | 借用其他项目解释器或 `PYTHONPATH` 拼装 |

参考实现：

- SQLite 朴素访问：`mingxi-shuihui`、`mingxi-admin`
- MySQL 朴素访问：`huisuoxiangcexitong`（PyMySQL）

## 2. 新建项目时的检查清单

1. 目录按《项目结构规范（房规v1）》搭骨架。
2. `pyproject.toml` **不**默认加入 `sqlalchemy` / `alembic`。
3. `backend/src/app/db/` 提供 `session.py`（连接）+ `schema.py`（幂等建表），模型用数据类或普通结构，不挂 ORM。
4. SQL 一律参数化（`?` / `%s` 占位），禁止拼字符串。
5. 启动脚本：建表用 `ensure_database()`，不要 `alembic upgrade`。
6. 虚拟环境只在本项目 `backend/.venv`（或约定路径），启动前自检本项目解释器。

## 3. 例外怎么批

允许例外，但必须同时满足：

1. 需求或方案里写明例外技术与原因；
2. 影响范围写清（仅本项目 / 仅某模块）；
3. 未批准前，AI **不得**把 ORM / 迁移框架加进依赖。

本机存量项目（huisuo / mingxi-shuihui / mingxi-admin / country-agent）已统一为朴素驱动；新建项目默认按上表，例外须在需求里写明理由。本机状态巡检在管理后台 `/machine`。
